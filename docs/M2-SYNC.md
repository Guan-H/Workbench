# 使用 M2 首批同步入口

当前已发布版提供网页设备配对/撤销、Windows 助手小窗口、简单安装入口和可可靠识别的文件改名/移动同步；修复版已于 2026-11-03 配套发布。它还不是完整 M2：仅接受新的空目录，沿用最多 5000 对象的全量快照；非空目录合并、增量分页、文件夹重命名迁移、正式冲突解决、正式安装包签名和开机启动仍待后续交付。不要用当前已安装助手接管已有 Obsidian 库；尚未发布的增量/分页开发进度见下方验证边界。

## 推荐：安装一次，以后双击图标

完整解压 2026-11-03 的启动优化包后，双击其中的 **安装同步助手.exe**，在应用窗口点击 **安装并创建快捷方式**。安装完成后，桌面和开始菜单会出现 **私有空间同步助手**，以后点击这个图标即可打开，不需要命令行或重新寻找解压目录。安装进度按实际复制并校验的文件数量显示，长错误信息可在窗口内部滚动。

程序安装至 `%LOCALAPPDATA%\Programs\PrivateSpaceSync\releases\<版本目录>`，配对、队列及配置继续留在原 `%LOCALAPPDATA%\PrivateSpace\Sync` 和旁置 `.profiles` 目录；同步文件仍在你选定的文件夹。更新创建独立程序版本并刷新快捷方式，旧版本不覆盖删除。安装失败不替换原有效安装记录；同名快捷方式指向其他程序时会停止，保留该快捷方式。此入口不写系统级设置，不开启开机启动，也不自动开始同步。

同一状态根目录再次启动新版助手，会唤起已有窗口，不另外启动同步进程。安装或更新前应从旧版窗口正常退出一次，尤其是还没有单实例唤起能力的历史版本。CLI 与使用不同 `--state` 的独立测试实例保持原语义；CLI 与桌面之间仍由既有状态锁防止并发写入。

本批构建目录为 `sync-client/dist/easy-start/privatespace-sync/`，分发包同时保留主程序、中文安装入口和 `_internal`。构建命令为 `./scripts/build-sync-desktop.ps1 -Variant easy-start`；不指定 Variant 时仍使用原默认构建目录。仍未提供系统卸载项、正式 MSI/签名安装包、自动更新、托盘或用户可选开机启动。

完整分发包为本地被忽略的 `data/workbench-sync-windows-easy-start-20261103.zip`。当前开发电脑已完成用户目录安装并创建两个快捷方式；若之前的旧版窗口仍在运行，先从该窗口正常退出一次，再使用新图标。安装后的程序默认恢复原选择并保持暂停，需手动开始监听。

## 启动本地助手

先按项目 README 启动 MySQL、后端和前端。网页地址是 `http://127.0.0.1:5173/`，助手的本地服务器地址填写 `http://127.0.0.1:8080`。

在项目根目录用 PowerShell 启动源码窗口：

```powershell
cd sync-client
python -m privatespace_sync gui
```

默认助手状态目录为 `%LOCALAPPDATA%\PrivateSpace\Sync`，与选定的同步文件目录分开。临时验证可显式指定独立状态目录：

```powershell
python -m privatespace_sync gui --state D:/ai_project/Workbench/data/m2-manual-state
```

也可以运行窗口版构建产物 `sync-client/dist/privatespace-sync/privatespace-sync.exe`。该产物是一个 onedir 目录，将程序与旁边的 `_internal` 一起保留；它尚未制作安装包或签名，不能只复制 EXE。重新构建命令为根目录的 `./scripts/build-sync-desktop.ps1`，复用原有固定依赖构建环境；该环境不存在时先按原型打包脚本准备，不另装 GUI 框架。

2026-11-02 目录结构修复另行构建在 `sync-client/dist/directory-sync/privatespace-sync/privatespace-sync.exe`，避免覆盖原程序。该目录同样须保留 `_internal`。先从旧助手窗口正常退出，再打开该版本，继续使用原配置并点击手动同步即可创建缺失的服务端目录结构；重新配对或清理原文件不是升级步骤。构建脚本默认路径不变，独立构建使用原固定 PyInstaller 环境并指定 `--distpath dist/directory-sync`。

## 更换服务器、重新配对或更换本地目录

窗口右上角点击 **更换服务器 / 目录**，输入新配置名称，点击 **新建配置并切换**。助手在当前安全文件操作结束后停止原配置监听，保留原文件、设备凭据、SQLite 队列及冲突记录；新配置的服务器、空目录和一次性配对码可重新填写。新配置需在对应服务器网页生成新配对码，不沿用旧服务器的令牌、队列或基线。

新配置配对失败时可修改输入重试，也可重新打开该窗口，选择原配置并点击 **使用选中配置** 切回。切换及重启均默认暂停，须手动开始监听或手动同步；未启用的配置不进行后台同步。配置列表每页 20 项并有滚动条，显示名称、服务器及选中目录；不会显示设备令牌。原服务器上的设备授权不会自动撤销，如不再使用可在原网页同步中心撤销。

已安装版更换本地目录仍采用新空目录重新同步，旧目录保留。开发源码版新增非空合并预检，见下节；两者都不能选择与任何已保存配置目录、助手状态目录重叠的路径，避免不同配置交替写同一目录。已有绑定目录须使用原配置，不能通过删除目录标记或状态文件绕过。

## 开发版：合并已有目录

本节仅适用于开发分支源码，当前配套后端为 V9，生产和已安装 EXE 尚未更新。使用独立开发状态启动：

```powershell
cd sync-client
python -m privatespace_sync gui --state D:/ai_project/Workbench/data/m2-merge-manual-state
```

1. 在本地网页同步中心选择设备范围、生成配对码；在助手填写 `http://127.0.0.1:8080` 并选择未绑定的目录。目录可以有内容。配对写入根目录标记和 DPAPI 凭据，不传业务文件。
2. 点击“手动同步”或“开始监听”。非空目录首先停在“首次合并待确认”；点击“查看合并预检”，核对上传、下载、一致、冲突、目录、跳过及持久化任务。每页 20 项，长内容内部滚动；可取消或重新预检，点击弹窗外不关闭。
3. 点击“确认并合并”才开始文件操作。相同路径相同字节建立映射、不新增服务器版本；相同路径不同字节保留服务器版本在原路径，本地内容另存冲突副本。服务器已有删除记录时，保留本地原文件与副本并记录冲突，不自动复活服务器文件。
4. 排除目录、范围外内容、超限、非法路径和链接均列出跳过项并保留，链接内部不读取。预检不上传本地纯空目录；原有服务器空目录仍会下载。处理后需同时查看冲突、问题和队列，不把本轮 `OK` 当成所有项均已完成。
5. 本地内容、远端版本或范围变化会使旧确认失效。执行部分完成后断网、暂停或退出，已完成的字节和 SQLite 队列保留，下次重新预检剩余状态；初始阶段不从缺失推断删除，不迁移改名。待操作完成后才进入日常同步。

存在根目录标记的目录、其子目录或含已绑定子目录的父目录都拒绝重新配对。旧配置继续使用原绑定；旧游标过期时使用下方重新对账流程，不能用“新配置接管同一目录”替代。

CLI 的 `pair` 默认仍要求空目录；已有目录需显式加 `--allow-existing`。之后 `once` 返回 `initialMergePreview`，核对当前 `fingerprint`，再执行 `once --state <状态目录> --confirm-initial-merge <fingerprint>`。该确认与 `--confirm-deletions` 相互独立，不能跨批使用。新绑定即使配对时为空，若首次执行前添加内容，也会进入合并预检；原有旧绑定不自动改成首次合并。

兼容旧版：原 `--state` 指定目录作为“默认配置”原样保留。管理信息存于该目录旁的 `<状态目录名>.profiles/registry.json`，新增配置的状态使用其中独立 UUID 子目录，凭据仍为 Windows 用户范围 DPAPI。备份助手状态时保留原状态目录及其旁的 `.profiles` 目录。CLI 的 `once/watch/status --state` 仍指定实际状态目录，不自动跟随 GUI 当前选择；当前实际路径显示在窗口底部，不直接编辑 JSON 切换配置。

## 配对并执行真实同步

1. 登录本地网页，打开左侧 **同步中心**。
2. 填写设备名称，选择 **全部同步** 或 **选择文件夹**。选择目录时可搜索并勾选多个目录，每页 20 项，超高内部滚动；选父目录自动包含其子目录，至少选择一个。生成一次性配对码，码有效约五分钟，只能使用一次，固定携带生成时的范围。页面退出后不持久化保留，码不要发到聊天或写入日志。
3. 在助手填写服务器地址，选择新建的空目录，粘贴配对码并点击 **配对**。配对成功只表示设备授权完成，尚未开始传文件。
4. 点击 **手动同步**，下载现有服务器笔记及附件；核对普通 Markdown 和图片实际文件。
5. 点击 **开始监听**。在本地新增或编辑测试文件后，查看网页服务器版本。网页可以关闭，监听由助手进程负责。
6. 点击 **暂停**，等待当前安全文件操作结束。暂停后自动监听停止，文件和 SQLite 队列保留；**手动同步**仍可执行一轮，不会悄悄打开自动监听。
7. 退出窗口会等待工作线程安全结束。重新启动后恢复本地配置和 DPAPI 凭据，默认保持暂停，需手动开始。

服务器保存、助手本轮检查完成和全部设备同步完成是不同状态。助手显示的队列/冲突/问题数量来自最近真实核对；网页“最近联系”只表示服务端收到有效设备请求的时间，“已授权”不表示实时在线。

## 只同步指定文件夹

配对时选择一个/多个目录，助手保留库内路径。例如勾选 `工作/项目A` 后，本地路径为 `所选本地目录/工作/项目A`，不会把其内容平铺到根目录。未选目录不扫描文件内容、不上传、下载或传播删除。

同步会先创建服务端所选目录及其子目录，包括没有文件的空目录；所选目录的必要祖先目录也会在本地建立。例如选择 `哈哈哈哈/BBBB`，本地根目录为 `C:\Users\14219\Desktop\sync_files_tow\ex`，请在 `ex\哈哈哈哈\BBBB` 中新建文件，开启监听后会上传至服务器同一路径。多个所选目录并列保留各自完整层级，不同父目录下的同名目录不会合并。本地根目录和未选路径内的文件不会自动归入某个所选目录。

目录与本地同名文件冲突时保留该文件，显示 `DIRECTORY_PATH_CONFLICT`；原有同步文件的父目录缺失时显示 `PARENT_DIRECTORY_UNAVAILABLE`，不会先重建空目录再推断服务器文件应删除。需要恢复目录或处理冲突后手动重试。服务器目录下载不代表已实现本地纯空目录上传、目录删除传播或目录重命名迁移，这些仍属后续同步范围。

网页设备行的 **修改范围** 可调整已有设备，仅影响该设备。范围按版本保存；若另一个页面先改了范围，旧提交会被拒绝。助手下一次对账获取新范围，对账期间使用旧范围的读写会被服务端拒绝。取消选择会保留两端已有内容及未提交上传队列，范围外队列暂存并单独显示数量，不继续发布；重新纳入时重新核对，不把范围切换时缺失的文件当作用户删除。

选中笔记的标准 Markdown 图片、附件链接会自动纳入其引用的库内附件，包含目录外共享附件，保留相对路径。只纳入附件，不递归跟随其他笔记或下载无关图片。新本地笔记需要先保存到服务端，助手再补扫新增的附件引用；窗口手动同步会自动补扫有限轮次，未完成时显示待处理，不伪报完成。CLI `once` 返回 `rescanRequired` 时再执行一轮。

目录外共享附件内容修改仍双向同步；如果仅在本地删除共享附件副本，助手会重新下载，不反向删除服务端的共享文件。取消目录选择或笔记不再引用附件，只停止纳入并保留本地副本。完整库模式或显式选中附件目录时仍适用原有删除同步及批量确认规则。

范围固定按库内目录路径匹配；如果在网页移动或重命名了所选目录，当前未实现范围自动迁移。旧范围不会自动扩大到新位置；需要在网页重选新路径。目录已删除时保留其原范围以接收范围内墓碑，但重新保存范围时须选择当前存在的目录。

选择性同步需本批新版助手。旧助手不理解选择过滤，不得继续运行受限设备；服务端要求范围版本头，已改范围的旧助手会被拒绝，不能以全库处理方式退化。

系统目录、助手状态目录和原有临时文件排除规则继续有效，不能通过勾选目录或附件引用绕过；所选目录仍须为库内当前存在的文件夹。

## 开发版：重新对账预检与确认

源码助手配对后提供“重新对账”。日志过期、服务器版本回退，或希望主动查看两端差异时，点击此入口；助手停止自动监听，重新读取真实服务器分页目录，不沿用旧游标继续补发。下方列表每页 20 项并支持滚动，展示内容一致、差异、仅本地存在、远端内容、无法确定的删除、目录、跳过项和保留的旧任务。点击“查看对账预检”打开确认窗口；取消不执行，预检有问题时先处理并重新预检。

确认前不上传、下载、删除、重放任务或替换现有游标/目录缓存/基线。读取快照仍会更新服务器设备联系状态和分页元数据。确认时重新检查两端，变化使旧确认失效。确认后，旧基线、上传/改名任务和相关状态先完整保存到本机状态库的对账归档，再建立新目录与游标，采用初始合并保护执行；不重放旧删除或旧改名，不因缺失自动删除或复活旧路径。

同路径不同内容保留双方；原基线或旧任务对应的路径已缺失时保留本地内容并登记冲突。旧队列中未出现在当前两端的内容仍保存在归档，登记待处理冲突。助手显示归档批次数，归档中的旧编辑可在下方单文件冲突处理入口查看并明确采用，不自动发布。中断后会保留归档并重新要求合并预检；完成后仍默认手动状态，冲突未处理时不会自动开始监听。不要删除状态库绕过保护。生产和已安装助手尚未更新。

## 开发版：助手冲突处理

在待处理列表中选中一条冲突，点击“处理选中冲突”。助手停止自动监听后读取服务器当前版本，展示当前本地文件、原冲突副本、对账归档旧编辑及上次处理保留的内容。版本列表每页 20 项、内部滚动；选择后查看文本或二进制片段，预览最多 64 KiB，实际采用完整字节。

点击“采用所选版本”才执行。选择服务器已删除/不存在的版本，意味着确认回收该路径的本地文件；本地原始字节先写入助手状态目录 recycle。选择本地/副本/归档内容会按当前服务器版本条件发布；当前有墓碑时可明确恢复原单文件，普通自动同步仍禁止复活墓碑。父目录已删除时须先在网页恢复父目录。未知旧路径已经不存在时，明确采用本地内容可创建新文件，不代表自动识别旧 ID 或目录迁移。

Markdown 可从所选版本打开手动合并窗口，点击保存才提交。版本变化拒绝旧选择，草稿保留在当前助手进程内存，可重新打开同一路径的合并编辑；尚未点击保存的草稿不会跨助手退出持久化。二进制不提供文本合并。确认后的处理计划保存到本机状态库，发生中断可点击“继续上次处理”；同一操作编号重试，不绕过版本条件。已有更新或范围变化会停止旧计划，保留其中内容供重新选择。原冲突副本、对账归档及回收副本不会自动删除。

此入口属于源码助手，须配套支持 `/api/v1/sync/conflict-files` 的后端，不会对旧服务器降级为无条件写入。网页直接选择并处理冲突、文件夹整体冲突及目录迁移仍在后续范围，不能把助手单文件处理通过视为完整 M2 关闭。

## 开发版：网页查看冲突记录

配套 V9 后端与源码 Tk 助手使用。在网页同步中心的设备行点击“冲突记录”，可按每页 20 条查看库内路径、原因、本地文件观察、最后确认基线、副本数量和上报时间，超出高度可内部滚动。复制路径后，在助手待处理列表选择该路径并点击“处理选中冲突”；网页目前不能读取本地正文、选择版本或远程执行文件操作。

Tk 助手在同步检查后、成功处理冲突或完成重新对账后尝试上报元数据。提交前先持久化，断网或退出后下次执行会继续；上报失败单独显示，不把已经成功的文件同步改写为失败。报告只包含库内路径和摘要等信息，不上传本地绝对路径、正文、冲突副本或对账归档。CLI `once/watch` 当前没有自动上报此状态。

网页展示的是最后成功上报的观察，不代表设备实时在线或所有本地变化已上传。未成功上报的设备显示状态未知；旧范围记录会标注需要重新核对，设备撤销后保留历史记录。暂停或未执行同步时不会持续刷新上报，查看时请核对时间。网页刷新或重试只读取记录，不会远程唤起助手。

## 处理暂停和删除预览

- 断网时自动模式按退避间隔重试，队列保留。授权失效、目录不可达、冲突和其他待处理项会暂停并显示实际代码。
- 同一状态目录只允许一个同步引擎写入，包括 CLI 和窗口版。出现 `STATE_IN_USE` 时先退出另一进程，不删除锁文件、SQLite 或设备凭据来绕过保护。
- 状态锁由新版源码 CLI 和本批窗口版共同遵守；旧 M0 已打包程序不包含新保护，不能与新版共用状态目录并行运行。
- 超过 20 项或已有文件数 10% 的删除或改名会暂停并生成具体预览。新版窗口中点击 **查看变更预览** 核对方向、旧路径和新路径，再确认当前批次。预览每页 20 项，有滚动条；范围较小时，一项变更也可能超过 10% 阈值。
- 新版在 Windows 文件身份可可靠确认时，将直接改名、改扩展名及文件移动同步为原服务端文件的路径变化，保留原 ID、收藏和历史。例如 `.txt` 改为 `.md` 后成为 Markdown 笔记，不额外生成一份；有效 UTF-8 和 1 MiB 笔记限额仍检查。其他新版设备按同一个 ID 更新本地文件名。改名期间的正文编辑、离线队列、响应丢失重试和旧名字被新文件复用均保留各自身份，不靠内容相同猜测改名。
- 服务端和助手需配套升级；旧服务器未声明支持时，新助手暂停可识别的改名并提示 `RENAME_SERVER_UPGRADE_REQUIRED`，不会退化为新增/删除。既有配置先在原名称下同步一次，以记录本地身份；旧版已造成的两份文件不自动合并。不支持可靠文件身份、复制后删除、跨卷复制或编辑器替换导致身份丢失时，仍保守按无法识别处理，保留原有删除保护。文件夹整体改名和所选范围自动迁移仍未交付。
- 目标重名、服务端并发修改或本地身份变化时暂停并保留文件；不自动覆盖，不自动改写其他笔记中的链接。问题列表与预览明确区分服务器改名、本地改名、服务器删除和本地回收。`remote` 删除方向仍表示等待删除服务器旧文件，不是网络故障。
- 前一批中文删除提示版位于 `sync-client/dist/image-rename-fix/privatespace-sync`，本机桌面/开始菜单入口已由下面的文件改名版替代。
- 新文件改名版位于 `sync-client/dist/file-rename-sync/privatespace-sync`，完整 ZIP 为 `data/workbench-sync-windows-file-rename-20261103.zip`。11 月 3 日服务端已配套发布，本机桌面/开始菜单入口已更新；正常退出旧窗口后重开，先手动同步一次。更新保留配置与队列，不自动开始同步或替用户确认变更。
- 已经进入待确认的批次，即使重启或数量下降到自动阈值以下，也保持待确认。变化后的批次必须使用当前 fingerprint；旧确认不放行新范围。全部完成或已无拟删除项后才清除待确认状态。
- 已发布助手只提供冲突副本和问题列表；开发源码的单文件处理入口见上一节。不要把本轮 `OK` 当作所有冲突已解决。
- 撤销设备后不会删除其已有本地文件，下一次设备请求会被拒绝并暂停。可用配置管理新建独立配置，选择新空目录重新配对；原非空目录接管尚未实现，旧队列与文件保留。
